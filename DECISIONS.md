# DECISIONS.md

Tiga bagian: keputusan terkunci (K), asumsi yang boleh diubah (A), dan pertanyaan terbuka (O). Agent menambahkan asumsi baru di bagian A dengan nomor berikutnya. Mengubah bagian K butuh persetujuan pemilik.

## Keputusan terkunci

- **K-01.** Posisi produk: LLM melengkapi scanner (augmentasi), bukan menggantikan. Dasar: `docs/DESIGN-TRACE.md` D-01.
- **K-02.** Invarian I-01 sampai I-10 di `SPEC.md` mengikat.
- **K-03.** Fable tidak dipakai untuk peran agent mana pun. Model tertinggi yang dipakai adalah Opus 5.5.
- **K-04.** Pembagian model: orkestrator dan developer Sonnet 5.5; reviewer dan architect Opus 5.5 effort medium; explorer Haiku 5.5. Developer naik ke Opus di fase 3, 7, 8, 10 dan setelah dua kegagalan gerbang.
- **K-05.** Kebijakan git: author commit adalah pemilik repo, tanpa atribusi Claude di commit maupun PR, hanya orkestrator yang commit dan push, hanya ke branch fase, tanpa force push.
- **K-06.** Repo ini terpisah dari tugas akhir dan paper pemilik. Hasil paper orang lain dipakai sebagai dasar desain dan pembanding, bukan dikutip sebagai hasil triagent.
- **K-07.** PDF literatur tidak pernah masuk git. Catatan ringkasan buatan sendiri boleh.
- **K-08.** Tidak ada tanda pisah panjang di dokumen repo.
- **K-09.** Tidak ada temuan yang dibuang otomatis (I-01), apa pun verdict modelnya.

## Asumsi (boleh diubah)

- **A-01.** Repo berdiri sendiri, bukan bagian dari repo tugas akhir.
- **A-02.** Inti ditulis dengan Python, `requires-python >=3.12`, diuji di 3.12 dan 3.13 (mesin pemilik 3.13); bahasa target analisis v1 adalah JavaScript dan TypeScript, benchmark berupa aplikasi Node.js (Express).
- **A-03.** Scanner pertama adalah Semgrep OSS karena lokal, berformat SARIF, dan tanpa akun. SonarCloud dan CodeQL menyusul. Di Windows, Semgrep dijalankan lewat image Docker resmi dengan versi dipin. Tes hanya memakai fixture SARIF.
- **A-04.** README dalam bahasa Inggris (repo publik); dokumen proses dalam bahasa Indonesia.
- **A-05.** `GUARD_LIMIT` bawaan 45 (persen meter mingguan, nilai absolut, bukan pemakaian harian). Ubah di `.claude/guard/config.env` sesuai kebutuhan dan setelah meter mingguan reset.
- **A-06.** Batas biaya bawaan per perintah eval berbayar adalah 5 USD, anggaran total diisi pemilik di prompt peluncuran.
- **A-07.** Field `effort: medium` di frontmatter agent belum diverifikasi didukung oleh versi Claude Code yang dipakai. Bila tidak didukung, atur effort lewat pengaturan model sesi. Diperiksa di Fase 0.
- **A-08.** Nilai `model: opus`, `sonnet`, `haiku` adalah alias. Pastikan di `/agents` bahwa alias menunjuk ke Opus 5.5, Sonnet 5.5, dan Haiku 5.5. Bila tidak, ganti dengan ID model lengkap (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`).
- **A-09.** Format aturan izin di `.claude/settings.json` (deny untuk `git config`, force push, dan membaca `.env`) diverifikasi lewat `/permissions` di Fase 0.
- **A-10.** Guard bergantung pada status line CLI. Bila memakai ekstensi IDE, status line tidak berjalan dan guard buta; gunakan terminal. Di Windows gunakan Git Bash atau WSL dan pastikan `jq` terpasang.
- **A-11.** Hook `PreToolUse` diasumsikan juga berlaku untuk pemanggilan alat di dalam subagent. Belum diverifikasi; tes di Fase 0 dengan `GUARD_LIMIT` sengaja diset rendah.
- **A-12.** Lisensi belum dipilih. Tanpa lisensi, repo publik berarti semua hak dilindungi. Pemilik memutuskan sebelum rilis.
- **A-13.** Atribusi: `attribution.commit` dan `attribution.pr` dikosongkan. Trailer URL sesi dikelola kunci lain di beberapa versi, jadi hook `commit-msg` menjadi pengaman cadangan. Periksa `git log -1 --format=full` setelah commit pertama.
- **A-14.** Status lifecycle dan hasil verifikasi adalah dua field terpisah; `verified` diturunkan dari `verification.result == exploitable` (R-01).
- **A-15.** Id Finding deterministik; duplikat disimpan dengan `duplicate_of`, tidak dibuang (R-02).
- **A-16.** Setiap panggilan LLM dicatat sebagai entitas `LlmCall` di audit log, termasuk yang gagal (R-03).
- **A-17.** Evaluasi v1 mengukur triase atas temuan scanner; deteksi tanpa scanner adalah roadmap (R-06).
- **A-18.** Tafsiran I-10: larangan panggilan berbayar berlaku untuk tes dan pengembangan repo ini; pemakaian produk dibatasi `budget` (sementara, menunggu O-05, R-04).
- **A-19.** Skema `Finding` Fase 1 menyimpang dari SPEC bagian 5 sesuai resolusi Fase 0: field `status` menjadi `lifecycle` (tanpa nilai `verified`, R-01); `cwe` berupa daftar (R-07); ada `duplicate_of` (R-02); `triage[]` hanya memuat `model_id`, `verdict`, `reason`, `confidence`, `call_id`, sedangkan `prompt_hash`, token, biaya, dan latensi pindah ke entitas `LlmCall` (R-03); `human_decision` memuat `actor` (`human` atau `rule`) dan `rule_id`. `verified` adalah properti turunan, bukan field masukan. JSON Schema hanya menjamin bentuk dan enum; aturan lintas-field (I-01, I-02, fix_validated) ditegakkan validator pydantic.
- **A-20.** Konfigurasi `.triagent.yml` Fase 1: `models` wajib (tidak ada bawaan); `redact: false` wajib disertai `redact_experiment` (I-03: hanya untuk eksperimen tercatat); `mode` yang memuat verify wajib `verify.enabled: true`; kunci tak dikenal ditolak. Nilai `scanners` dibatasi semgrep, sonarcloud, codeql.
- **A-21.** Hash kepala audit log disimpan di berkas samping `<log>.head` (hash terakhir dan jumlah entri). Berkas ini berada di folder yang sama sehingga penyerang yang bisa menulis log juga bisa menulisnya; perlindungan penuh butuh `--expected-head` dari metadata run yang disimpan di tempat lain. Belum ada penulis metadata run (Fase 3). Penghapusan log dan head sekaligus hanya terdeteksi lewat `--expected-head`; `verify` menolak log yang hilang, kosong tanpa head, atau berisi baris kosong.
- **A-22.** Batas yang diterima setelah review Fase 1 (siklus 1): (a) model immutable (`frozen`), `model_construct` dimatikan, `model_copy(update=...)` divalidasi ulang, `transition()` memvalidasi ulang masukan; `object.__setattr__` dan mutasi list (`triage`, `cwe`) tetap mungkin dan hanya dijaga grep gerbang atas `src/`; (b) `rule_id` belum dicek ke registri aturan dan `reason` belum diredaksi (I-09), ditutup di fase aturan suppress dan redaksi; (c) `actor` dicek saat runtime; (d) audit log dikunci OS (`<log>.lock`) dan head direkonsiliasi saat append, hanya penghapusan total log dan head tanpa `--expected-head` yang tak terdeteksi; (e) Python 3.12 baru terbukti saat CI GitHub jalan, orkestrator memeriksa run CI branch fase sebelum titik cek, gerbang tidak mem-parse ci.yml; (f) `append` O(n) karena membaca seluruh log.
- **A-23.** Id Finding (R-02) = `f-` + 24 hex pertama SHA-256 dari JSON `[tool, rule_id, file, kunci isi, nomor kemunculan]`. Kunci isi: nilai `partialFingerprints` yang nyata bila ada, jika tidak potongan kode ternormalisasi (spasi dirapatkan), jika tidak nomor baris. Map `fingerprints` SARIF diabaikan karena Semgrep OSS mengisinya dengan placeholder "requires login". Nomor baris tidak masuk id bila potongan kode ada, jadi id tahan terhadap pergeseran baris; dua alert identik dibedakan nomor kemunculan (diurutkan menurut baris, kolom, lalu urutan di berkas).
- **A-24.** Tabel keluarga CWE (R-07) ada di `src/triagent/normalize/data/cwe-families.yaml` (bukan `config/`, supaya ikut paket yang dipasang). Dihasilkan oleh `scripts/build_cwe_families.py` dari katalog MITRE CWE v4.20 (2026-04-30, view 1000, sha256 tercatat di `meta`). Aturan keluarga: leluhur terdekat (BFS lewat ChildOf, id terkecil bila seri) berabstraksi Class atau Pillar; Pillar dan id yang tidak terdaftar adalah keluarganya sendiri. Contoh yang dipakai tes: 79 -> 74, 95 -> 74, 89 -> 943, 78 -> 77, 601 -> 610, 862 dan 863 -> 285. Satu-satunya data manual: kelompok 862/863 (keluarga 285). Itu terverifikasi pada v4.20 (keduanya ChildOf 285 di view 1000, dicek oleh skrip pembangun), tetapi bila katalog MITRE berubah, skrip pembangun akan gagal pada asersi itu dan kelompok harus ditinjau. Akibat aturan: XSS (79) dan Eval Injection (95) satu keluarga (CWE-74) di varian longgar, sedangkan XSS dan SQL injection (89) serta command injection (78) tidak. Granularitas keluarga tidak seragam (78 di 77, tetapi 77 sendiri di 74); itu sifat hierarki MITRE, bukan keputusan manual.
- **A-25.** Dedup (Fase 2): dua temuan duplikat bila berkas sama dan rentang baris (diperlebar `line_window`, bawaan 2) bertumpuk dan keluarga CWE beririsan (CWE ganda: cukup satu irisan). Dua alert dari aturan dan alat yang sama harus bertumpuk persis (kemunculan berdekatan dari satu aturan adalah temuan berbeda). Bila salah satu tanpa CWE, hanya pasangan alat dan aturan yang sama yang bergabung. Lokasi tidak dikenal (`<unknown>`) tidak pernah digabung. Kanonik dipilih menurut severity scanner, baris, rule_id, id; duplikat hanya dibandingkan dengan kanonik (tanpa rantai), jadi hasil tidak bergantung urutan masukan. Duplikat tetap ada, berstatus `deduped`, dengan `duplicate_of` (I-01). Nilai `line_window=2` dan aturan "satu aturan harus bertumpuk" adalah keputusan teknik tanpa dasar literatur; belum divalidasi pada benchmark (Fase 3).
- **A-26.** Parser SARIF tidak membuang result yang berbentuk objek: result tanpa lokasi mendapat berkas `<unknown>` baris 1 plus peringatan; `endLine < startLine` diperbaiki jadi `startLine`; level tak dikenal menjadi `None`. Elemen `results` yang bukan objek dicatat di `skipped` dan perintah `triagent ingest` keluar dengan kode 2 setelah menulis keluaran. Dokumen yang bukan SARIF 2.1.x (JSON rusak, akar bukan objek, versi lain, `runs` bukan daftar) ditolak dengan `SarifError` (kode keluar 1). Hanya CWE di awal tag yang diambil (`CWE-79: ...`, `cwe-079`, `external/cwe/cwe-089`); CWE-0 dan teks "not CWE-5" dibuang. Taksonomi/relationships SARIF (misalnya CodeQL) belum dibaca: belum diketahui apakah perlu, ditunda sampai adapter CodeQL.
- **A-27.** Adapter Semgrep menjalankan `docker run --rm --mount ...,readonly` dengan image yang dipin digest (`semgrep/semgrep@sha256:3db5c7af...`, versi 1.181.1), `--metrics=off`, paket aturan registri `p/...` atau `r/...` saja (`auto` ditolak karena menuntut metrik), SARIF dari stdout, batas waktu 900 detik. Kontainer memuat aturan dari registri Semgrep sehingga butuh jaringan; kode Python tidak membuka koneksi. Tes tidak menjalankan Docker. Fixture `tests/fixtures/sarif/semgrep-1.181.1-js-sample.sarif` adalah keluaran nyata (lihat `PROVENANCE.md`); R-05 menyebut `tool.driver.version`, kenyataannya Semgrep mengisi `tool.driver.semanticVersion`. Satu run Docker nyata lewat `triagent ingest --run-semgrep` menghasilkan temuan identik dengan golden (dijalankan manual sekali, tidak ada di gerbang karena gerbang offline).
- **A-28.** Benchmark Fase 3 (tahap A). (a) Aplikasi `benchmark/app` (`fieldnotes-bench`, Express 4.22.3, JavaScript) ditulis orisinal: 13 item TP dan 10 jebakan FP dalam 11 kategori. Label bersumber dari PoC (keluar 0 untuk TP, 1 untuk jebakan), bukan dari LLM. Database diganti mesin SQL mini (`lib/minisql.js`) supaya tanpa dependensi native; scanner dengan aturan khusus driver basis data bisa tidak menyala pada item SQLi. (b) Jalur R-08: PoC dan aplikasi hanya jalan lewat `docker compose` (`benchmark/docker/compose.yaml`) pada jaringan `internal: true`, tanpa port terbit, kontainer non-root, rootfs baca-saja, `cap_drop ALL`, `no-new-privileges`, batas CPU, memori, PID; sumber app dan PoC dipasang baca-saja; app dimulai ulang sebelum tiap PoC. Image hanya memuat dependensi (`npm ci` dari lock) dan dibangun sekali; itu satu-satunya langkah yang butuh jaringan registry, dan dijalankan oleh `triagent benchmark poc` atau `selftest` bila image belum ada. Ini bukan sandbox Fase 7 (tanpa PoC buatan LLM, tanpa batas waktu per eksekusi selain 90 detik). (c) Skema `schemas/ground-truth.schema.json` dihasilkan dari model pydantic; aturan yang butuh berkas (baris dalam berkas, PoC ada, `anchor`) ada di `validate_root`. `anchor` adalah teks yang tidak berubah oleh mutasi (nama properti, string) dan harus ada di baris item; ini bukti independen bahwa baris varian bergeser benar. (d) Generator mutasi memakai tokenizer JS sendiri (`src/triagent/benchmark/jsmini.py`), bukan parser penuh. Batas yang diketahui: tanda `/` setelah `}` dianggap pembagian; nama yang dipakai sebagai properti, nama metode, atau di posisi shorthand atau destructuring tidak di-rename; tanpa dukungan TypeScript atau JSX. Kebenaran varian dibuktikan oleh validasi, `node --check`, dan PoC yang dijalankan pada varian, bukan oleh pembuktian formal. (e) Batas ground truth: ditulis oleh agent developer dan dikonfirmasi PoC, belum oleh manusia kedua (risiko sirkularitas, lihat catatan anggoman-2025 dan sifting-noise-2026). Item prototype pollution menunjuk fungsi merge, bukan titik pemanggilan. Belum ada run Semgrep nyata pada benchmark di tahap A, jadi belum diketahui berapa item yang terdeteksi scanner dan apakah O-09 cukup.
- **A-29.** Evaluasi Fase 3 (tahap B), semua keputusan teknik tanpa dasar literatur kecuali dicatat. (a) `uncertain` dihitung dua arah (positif dan negatif) dan keduanya dilaporkan; prediksi positif tanpa `--verdicts` berarti semua temuan positif (baris dasar scanner saja). (b) Kecocokan item bersifat satu-ke-satu (review siklus 1, R-01): satu temuan diberikan ke paling banyak satu item, dipilih menurut jarak baris terkecil (0 bila rentang bertumpuk, dan jarak harus paling jauh sama dengan toleransi), lalu CWE ketat sebelum keluarga, lalu id item terkecil, karena satu temuan adalah satu prediksi dan dihitung dua kali akan menggelembungkan TP dan FP. Berkas harus sama, toleransi bawaan 2 dan bisa diubah, CWE ketat (id sama) atau longgar (keluarga sama, I-05). Validator ground truth menolak dua item di berkas yang sama dengan keluarga CWE yang sama bila jaraknya kurang dari atau sama dengan 2 x toleransi + 1 (BM-022 dipindah ke `routes/docs.js` karena ini). Temuan dengan `duplicate_of` dilewati (`duplicates_skipped`). Path temuan dicocokkan setelah `--strip-prefix` (boleh berulang); bila nol temuan cocok padahal ada temuan, ada peringatan di stderr dan `warnings` di laporan. Metadata rekaman memakai daftar putih (kunci wajib dan opsional `recorded_at`, `cassette_id`, `max_output_tokens`, `top_p`, `seed`); kunci lain dibuang dan hanya namanya dicatat di `dropped_meta_keys` (I-09). Perbaikan siklus 1 lain: nama rute jebakan dibuat netral dan diperiksa `triagent benchmark check-names` (kata safe, trap, vuln, secure, benign, exploit, fp, tp tidak boleh ada di identifier, string, dan nama berkas pada kode tanpa komentar; hanya pesan penolakan di `server.js` dikecualikan); selftest isolasi berjalan di kontainer poc dan app dengan 13 kunci tetap; base image dipin digest dan hasil PoC memuat `base_image_digest` dan `image_id`; respons 500 tidak memuat `err.message`; `GET /notes/:id` publik by design. (c) TP yang tidak ditemukan scanner (`fn_missed`) masuk recall tetapi tidak masuk TP retention; jebakan yang tidak ditandai scanner (`not_flagged`) tidak masuk FPR. Rasio dengan penyebut nol bernilai `null`. (d) Temuan yang tidak cocok item mana pun dilaporkan terpisah dan tidak dihitung FP; adjudikasi manual di berkas terpisah belum ada alatnya. (e) Run resmi minimal tiga per konfigurasi dengan sebaran dilaporkan; ambang kestabilan belum ditetapkan (belum diketahui, perlu data run nyata di Fase 4). Prompt dibekukan dan di-hash sebelum run resmi. (f) Mode rekaman: berkas JSON berisi metadata dan satu catatan panggilan per temuan (verdict, biaya, latensi, terpotong); `eval run` tidak membuka jaringan (I-10) dan menolak metadata tak lengkap atau panggilan yang hilang. Pencatatan `LlmCall` penuh (I-06) baru ada di Fase 4; format rekaman akan disesuaikan saat itu.

- **O-06.** Dukungan Semgrep native di Windows: belum diketahui.
- **O-07.** Venue dan DOI paper huynh-uwa: belum diketahui (PDF tidak memuat venue maupun DOI).
- **O-08.** Pendanaan dan konflik kepentingan belum diperiksa untuk gnieciak-2025, huynh-uwa, rajapaksha-2024, dan belum terlihat di teks sifting-noise-2026, contextual-bias-2026, chasing-shadows-2026, koterba-2026 (hanya pernyataan tanpa konflik).
